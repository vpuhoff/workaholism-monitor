# Workaholism Monitor

Мобильное веб-приложение для режима 25 минут работы / 5 минут отдыха. React, TypeScript, Vite, MediaPipe Face Landmarker, IndexedDB и PWA. Видеопоток обрабатывается на устройстве и не записывается.

## Запуск

Требуются Node.js 22+ и npm 11+. Если установлен npm 10, используйте `npx npm@11 install` для установки зависимостей.

```bash
npm install
npm run dev
```

Открыть http://localhost:5173. При установке скрипт `postinstall` копирует WASM из закреплённой версии MediaPipe и скачивает модель Google в `public/mediapipe`. Первичная установка требует интернета. Для повторной подготовки ресурсов: `npm run assets`.

```bash
npm test        # тесты машины состояний
npm run build  # TypeScript + production-сборка и service worker
npm run preview
```

Production-файлы находятся в `dist/`. Для доступа к камере на телефоне нужен **HTTPS**; HTTP по LAN-IP не подходит. PWA устанавливается из меню браузера или кнопкой внизу страницы, если браузер предоставляет событие установки. После полной загрузки service worker сохраняет интерфейс, модель и WASM для офлайн-работы. Шрифт опциональный, при отсутствии сети используется системный.

## Поведение

- Нажатие «Начать работу» разблокирует звук и запрашивает фронтальную камеру. Работа начинается при обнаружении лица.
- В рабочем режиме первые 10 секунд отсутствия учитываются как работа; затем таймер замораживается. Пять минут отсутствия, считая от первой потери лица, завершают добровольный перерыв.
- В 20–25 минут фон плавно становится красным. В 25 минут — сигнал, затем повтор каждую минуту переработки.
- Уход во время переработки сразу запускает отдых. Возвращение ставит отдых на паузу, не сбрасывая накопленное время. При нарушении отдыха сигнал звучит раз в минуту.
- Скрытая вкладка и разрыв между обработанными кадрами более 3 секунд приостанавливают учёт. Отсутствие кадров не считается отсутствием пользователя. После возврата отсчёт продолжается без учёта неподтверждённого интервала.
- Screen Wake Lock запрашивается по возможности. Работа камеры с выключенным экраном не гарантируется браузерами; фоновые push-уведомления без сервера не реализованы.
- «Завершить сессию» освобождает камеру и сохраняет незавершённую фазу. Перезагрузка начинает новую сессию. Завершённые фазы сохраняются сразу; при аварийном закрытии браузера текущая незавершённая фаза может потеряться.

## Статистика

События FSM хранятся в IndexedDB. Кроме полей ТЗ сохраняются `session_id`, абсолютные timestamps и `completed`. Время — локальное, длительность — фактически учтённые секунды. Паузы не включаются. Фазы отдыха разделяются при нарушениях; количество успешных перерывов считается по уникальным сессиям. Карточки учитывают уже сохранённые фазы, а не текущий таймер. События относятся к дате начала фазы; heatmap показывает часы начала рабочих фаз. Доступны тренд средней переработки за 7 дней, доля переработок за сегодня, качество отдыха за всю историю и экспорт JSON/CSV.

## Диагностика

Открыть `/?debug` или включить «Диагностика камеры» в настройках. Видео и точки лица скрыты по умолчанию. Частота CV — 2–5 кадров/с, по умолчанию 3. Три порога чувствительности применяются при следующем запуске камеры.

## Структура

- `src/lib/engine.ts` — независимая от UI машина состояний и события.
- `src/lib/camera.ts` — камера, MediaPipe и контроль свежести кадров.
- `src/lib/storage.ts` — IndexedDB, настройки и экспорт.
- `src/components/Statistics.tsx` — метрики и графики.
- `src/App.tsx` — жизненный цикл наблюдения и интерфейс.

## Проверка в браузере

```bash
npx playwright install chromium --no-shell
npm run build
npm run preview # оставить запущенным на порту 4173
# в другом терминале:
npm run test:browser
```

Проверка использует Chromium с тестовой камерой: загрузка настоящей модели MediaPipe, запуск и освобождение видеопотока, отказ в разрешении, настройки, IndexedDB, JSON-экспорт, мобильная ширина и повторный запуск CV в офлайн-режиме. Наличие реального лица, качество распознавания при вашем освещении и звук на физическом устройстве проверяются вручную. Адрес можно изменить переменной `TEST_URL`.

## HTTPS через Docker Compose

Приложение обслуживает nginx в контейнере. На хосте публикуется `0.0.0.0:443`, адрес — **https://virtual-ubuntu**. Порт 80 не используется, поскольку на этой машине он занят другим сервисом. Готовая production-сборка монтируется из `dist/` только для чтения; Node.js внутри работающего контейнера не нужен.

Первый запуск (Node.js/npm, Python 3, OpenSSL, Docker Compose):

```bash
npm install
python3 scripts/generate-certs.py 192.168.10.13 100.97.56.79
npm run build
docker compose up -d --wait
```

Скрипт всегда включает `virtual-ubuntu`, `localhost`, `127.0.0.1`; дополнительные IP или DNS-имена передаются аргументами. При смене адреса повторите генерацию с нужными именами и перезапустите nginx. Закрытый ключ CA хранится отдельно в `deploy/ca-private/` и не монтируется в контейнер. Сертификат сервера действует 365 дней; повторный запуск скрипта перевыпускает его, сохраняя прежний CA. Каталоги с сертификатами и ключами исключены из Git.

### Доверие сертификату на клиентском устройстве

Локальный CA не входит в стандартное хранилище доверия браузеров. На **устройстве, где открываете сайт**, импортируйте публичный файл `deploy/certs/local-ca.crt` как доверенный корневой центр сертификации. Только HTTPS с доверенным сертификатом позволяет надёжно использовать камеру и service worker. Простого пропуска предупреждения браузера может быть недостаточно.

- **Windows:** скопируйте файл на клиент и выполните `certutil -user -addstore Root local-ca.crt`, либо импортируйте через мастер в «Доверенные корневые центры сертификации» текущего пользователя.
- **macOS:** импортируйте сертификат в «Связку ключей», откройте настройки доверия и разрешите доверие для SSL.
- **Ubuntu/Debian:** скопируйте сертификат в `/usr/local/share/ca-certificates/workaholism-monitor.crt`, выполните `sudo update-ca-certificates`. Если браузер использует своё хранилище, импортируйте CA в его настройки сертификатов.
- **Firefox:** Настройки → Приватность и защита → Сертификаты → Просмотр сертификатов → Центры сертификации → Импортировать; разрешите идентификацию веб-сайтов.

Перезапустите браузер, откройте **https://virtual-ubuntu** и разрешите камеру. Сертификат доступен также по `/local-ca.crt`; для первичного импорта удобнее скопировать файл с сервера. Передавайте только публичный `.crt`, не файлы `.key`. Системные хранилища доверия автоматически не изменяются.

Имя `virtual-ubuntu` должно разрешаться в IP сервера на клиентском устройстве. При необходимости добавьте `192.168.10.13 virtual-ubuntu` в его hosts-файл. Можно также открыть https://192.168.10.13 — этот адрес включён в текущий сертификат.

### Управление

```bash
docker compose ps
docker compose logs --tail 50 nginx
# После изменений исходников:
npm run build
docker compose restart nginx
# Продление сертификата с тем же корневым CA:
python3 scripts/generate-certs.py 192.168.10.13 100.97.56.79
docker compose restart nginx
# Остановка:
docker compose down
```

Другой порт: `HTTPS_PORT=8443 docker compose up -d`, затем https://virtual-ubuntu:8443.

Проверка сертификата и ответа без отключения TLS-проверки:

```bash
curl --cacert deploy/certs/local-ca.crt \
  --resolve virtual-ubuntu:443:127.0.0.1 https://virtual-ubuntu/
```

При переходе с HTTP на HTTPS меняется origin: история IndexedDB и разрешения камеры не переносятся автоматически. При необходимости сначала экспортируйте историю из старого адреса.
