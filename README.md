# Workaholism Monitor

Личный таймер работы и отдыха. Цикл простой: 25 минут у экрана, затем 5 минут в стороне от него. Приложение само замечает, сидите вы перед камерой или уже отошли, и не даёт переработке пройти незамеченной.

Это мобильное веб-приложение, его можно поставить на телефон или компьютер как PWA. Фронтальная камера и MediaPipe Face Landmarker работают в браузере. Видео остаётся на устройстве: наружу уходит только факт, есть лицо в кадре или нет. Сервер хранит общую историю сессий между своими устройствами.

## Как проходит сессия

«Начать работу» запрашивает камеру и разрешает звук. Отсчёт начинается, когда в кадре появляется лицо.

Пока идёт работа, короткая потеря лица — до 10 секунд — всё ещё считается работой. Дольше таймер стоит на паузе. Если не возвращаться пять минут с момента, когда лицо пропало, незавершённая работа сохраняется как добровольный перерыв и сессия заканчивается.

К 20-й минуте фон начинает краснеть, к 25-й становится красным. В 25 минут звучит сигнал. Дальше каждая минута у экрана — переработка, и сигнал повторяется раз в минуту. Стоит отойти, начинается отдых.

Отдых длится пять минут без лица в кадре. Короткое возвращение ставит его на паузу и раз в минуту напоминает отойти. Если остаться дольше минуты, это время снова записывается как переработка. Чтобы пятиминутный отдых начался заново, нужно отойти хотя бы на минуту.

Скрытая вкладка и разрыв между кадрами больше трёх секунд останавливают учёт. Пропажа кадров не считается уходом. После возвращения отсчёт продолжается, пропущенный интервал в него не входит. Приложение просит браузер не гасить экран. Камера при выключенном экране зависит от браузера, отдельных push-уведомлений нет.

«Завершить сессию» отпускает камеру и записывает текущую фазу. Завершённые фазы пишутся сразу. Если браузер закрылся аварийно, незаконченная фаза может не сохраниться. Перезагрузка страницы начинает новую сессию.

## Статистика и данные

На устройстве история лежит в IndexedDB `workaholism-monitor`: фазы, длительность, дата, `session_id` и признак завершения. В длительность входят только секунды, которые таймер реально засчитал. Паузы туда не попадают. Карточки и графики читают уже записанные фазы. Переработка — это и обычная переработка после 25 минут, и переработка во время отдыха. Есть доля переработок за сегодня, средняя переработка за 7 дней, качество отдыха и тепловая карта часов, когда начиналась работа. Историю можно выгрузить в JSON или CSV.

Настройки камеры и звука лежат в `localStorage` (`monitor-settings`). Код синхронизации хранится там же, отдельно (`monitor-sync`).

Общая копия истории — SQLite, в контейнере API это файл `/data/events.db`. В базе хранилище и события. От кода остаётся только SHA-256, сам код сервер не помнит. Видео, кадры, точки лица и настройки камеры в SQLite не попадают. Удаление истории в браузере серверную копию не стирает.

Смена адреса сайта меняет origin браузера. Локальная история и код со старого адреса остаются там; на новом адресе код вводят заново через «Подключить по коду».

## Синхронизация

В настройках первое устройство нажимает «Включить синхронизацию» и показывает код из 64 hex-символов. Второе открывает тот же адрес и подключает этот код. Истории объединяются по `id` события. Учётной записи нет: кто знает код, может читать историю и добавлять события.

Событие сначала пишется в IndexedDB, затем уходит в API пакетами по 200. Обмен повторяется при открытии статистики, возвращении сети или вкладки, запуске приложения и раз в минуту, пока вкладка видима. Без сервера таймер продолжает работать, очередь уйдёт позже. Одинаковый `id` на сервере не перезаписывается.

«Перевыпустить код» оставляет историю хранилища и сразу отзывает старый код. «Отключить на этом устройстве» забывает код только в этом браузере. Общей кнопки удаления серверной истории нет.

## Локальная разработка

Нужны Node.js 22+ и npm 11+. Если в системе npm 10, зависимости ставятся через `npx npm@11 install`.

```bash
npm install
npm run dev
```

Интерфейс: http://localhost:5173. `postinstall` копирует WASM MediaPipe и скачивает модель в `public/mediapipe`, для этого нужен интернет. Повторить загрузку: `npm run assets`.

```bash
npm test                 # машина состояний
npm run build            # TypeScript, production-сборка, service worker
npm run preview          # собранный интерфейс на порту 4173
```

API для локальной синхронизации:

```bash
npm ci --prefix server
npm run generate --prefix server
npm run migrate --prefix server
npm start --prefix server
```

API слушает `3001` и пишет в `server/dev.db`. Vite проксирует `/api` на этот порт. Переменные: `DATABASE_URL`, `HOST`, `PORT`. В контейнере база — `file:/data/events.db`.

```bash
npm run check --prefix server
npm run test:sync
npm run test:browser
```

`test:sync` поднимает временные API и preview на портах 3001 и 4175. `test:browser` ждёт уже запущенный preview на 4173 и Chromium (`npx playwright install chromium --no-shell`). Адрес браузерной проверки меняется переменной `TEST_URL`. Живое лицо, свет и звук на телефоне эти тесты не проверяют.

Диагностика камеры: `/?debug` или переключатель в настройках. Частота распознавания — 2–5 кадров в секунду, по умолчанию 3. Пороги применяются со следующего запуска камеры.

## Свой сервер

Камера и установка PWA требуют HTTPS с сертификатом, которому доверяет браузер. В репозитории два способа поднять интерфейс и API рядом: Docker Compose на одной машине и манифест Kubernetes.

Compose публикует nginx на порту 443 (`HTTPS_PORT`, если нужен другой). API слушает только внутри сети Compose, браузер ходит на `/api` через nginx. История сессий лежит в томе `session-logs`. `docker compose down -v` этот том удаляет.

```bash
npm install
python3 scripts/generate-certs.py your-host.example 192.168.1.10
npm run build
docker compose up -d --build --wait
```

`scripts/generate-certs.py` выпускает локальный CA и сертификат сервера. В имена всегда входят `virtual-ubuntu`, `localhost` и `127.0.0.1`; свои DNS-имена и IP передайте аргументами. Закрытый ключ CA остаётся в `deploy/ca-private/`. На каждом устройстве, где открываете сайт, импортируйте `deploy/certs/local-ca.crt` как доверенный корень и открывайте тот адрес, который указан в сертификате.

Манифест `deploy/k8s/workaholism-monitor.yaml` описывает те же две части. `web` — ClusterIP на порту 8080, он отдаёт собранный интерфейс и проксирует `/api`. `api` — ClusterIP на порту 3001, наружу его публиковать не нужно; при старте применяются миграции. SQLite монтируется в `/data` с PVC `session-logs`. Ingress класса `tailscale` открывает только `web`; имя в `tls.hosts` становится именем устройства в tailnet.

Образы: `docker.io/library/workaholism-monitor-api:local` из `server/Dockerfile` и `docker.io/library/workaholism-monitor-web:local` из `deploy/web.Dockerfile`. Для веб-образа контекст сборки — каталог с `Dockerfile`, `nginx.conf` (`deploy/nginx/k8s.conf`) и `dist/` после `npm run build`. В манифесте стоят `imagePullPolicy: Never` и `nodeName: cube`: подставьте свой узел и способ, которым образы попадают на него, а StorageClass и IngressClass — те, что есть в вашем кластере.

## Структура

- `src/lib/engine.ts` — машина состояний и запись фаз.
- `src/lib/camera.ts` — камера, MediaPipe и свежесть кадров.
- `src/lib/storage.ts` — IndexedDB, настройки и экспорт.
- `src/lib/sync.ts` — код синхронизации и обмен с API.
- `src/components/Statistics.tsx` — метрики и графики.
- `src/App.tsx` — экран таймера и жизненный цикл наблюдения.
- `server/` — API, схема Prisma и миграции SQLite.
- `shared/events.ts` — общий формат события.
- `compose.yaml` — API и nginx на одной машине.
- `deploy/k8s/workaholism-monitor.yaml` — те же части для Kubernetes.
- `deploy/web.Dockerfile`, `deploy/nginx/k8s.conf` — образ интерфейса.
